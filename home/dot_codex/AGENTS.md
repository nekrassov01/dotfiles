# Preferences

## Working approach

- Precedence (highest first): org-managed settings, project-specific rules, this guide.
- Unless project-specific rules say otherwise, prioritize overall design and codebase-wide consistency over minimal diffs. Do not avoid necessary related changes merely to keep the diff small.
- Read enough related implementation, callers, tests, documentation, and similar code to understand the design and broader impact before deciding what to change.
- Resolve ambiguities about requirements during planning. Obtain agreement before sacrificing an existing quality to improve another. Once the plan is agreed, proceed within its scope without repeated confirmation.

## Language

- Chat: Japanese
- Code comments, documentation, pull requests: follow each project's conventions
- Commit messages: English

## Documentation

- Use proper heading levels instead of bold, with a consistent heading hierarchy.
- Prefer lists and tables over long prose. Avoid excessive bold, underline, or italics.
- In Japanese prose, avoid overusing the middle dot (・); prefer commas or particles like と / や.
